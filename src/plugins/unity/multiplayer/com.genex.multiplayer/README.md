# Genex Multiplayer for Unity (`com.genex.multiplayer`)

A thin client for the Genex relay, [protocol 3](../../packages/multiplayer/PROTOCOL.md), and for server-authoritative rooms, [protocol 4 (§17)](../../packages/multiplayer/PROTOCOL.md#17-authority-rooms-protocol-4), layered on the official Colyseus Unity SDK 0.18.8. The protocol is normative; this package follows it.

- `Runtime/Core/`: the Genex layer. It is plain C# with no `UnityEngine` references, and it compiles against the NuGet `Colyseus` 0.18.8 (netstandard2.1). `Runtime/Core/Authority/` is the authority client.
- `Runtime/Unity/` and `Runtime/WebGL/`: the Unity glue. A frame pump, the WebGL identity bridge and the world exporter's two marks.
- `Editor/`: the world exporter ([From a level to a world](#from-a-level-to-a-world)). `Editor/Core/` has no `UnityEngine` either.

## Install

1. Add the official Colyseus SDK 0.18.8. In `Packages/manifest.json`, the `upm` branch commit of 0.18.8 is:
   ```json
   "io.colyseus.sdk": "https://github.com/colyseus/colyseus-unity-sdk.git#7306c8ee4be7e78984baf0837df5ea8125154820"
   ```
   The release's `Colyseus_Plugin.unitypackage` works too. UPM cannot declare a git dependency, so you add it yourself.
2. Add this package, either from disk (`file:../../sdks/unity`) or by git URL with `?path=sdks/unity`.

You need Unity 2021.3 or later, for C# 8 and the `makeDynCall` jslib macro.

## Quickstart

```csharp
var session = GenexPump.Register(await GenexMultiplayer.Connect(new GenexConnectOptions {
    Urls = relayUrls, GameId = "my-game", Name = "ada",
    GetEmbedToken = GenexWebGL.EmbedToken,      // or nativeIdentity.TokenProvider
}));
session.SetState(new Dictionary<string, object> { ["x"] = 1.0, ["y"] = 2.0 });   // on a ~15 Hz tick
foreach (var p in session.Players.Values) if (!p.IsMe) Draw(p.Id, p.State);        // smoothed
var r = await session.Claim("ball");                                                // r.Accepted, r.Reason
if (r.Accepted) session.SetObject("ball", new Dictionary<string, object> { ["x"] = 3.0 });
```

There is a full sample under `Samples~/Quickstart`; import it from the Package Manager.

Values use one model: `null`, `bool`, `double` (every number), `string`, `List<object>` and `Dictionary<string, object>`. Every number goes out as msgpack float64. The layer never sends int64 or float32. Read values with `GenexJson.Num/Str/Bool/Map/List`.

### Behaviour

- **Reconnect.** The SDK's in-place reconnect uses the §8 settings: `minUptime 0`, 125/100/4000 ms, 9 retries, no queue. After it, the post-reconnect sequence runs: wait for the first full state (2 s cap), rebase history if the gap was over 1 s, resend pending controls with the same `requestId`, re-request chat, then raise `Reconnected`. `IsHost` stays false until that sequence completes. Nothing is ever sent on a closed socket.
- **Interpolation.** Remote players and objects use §10, on each sender's clock: a per-sender min-offset window, adaptive delay from 90 to 300 ms, extrapolation up to 250/150 ms, output ease with τ 30/70 ms, and a soft handoff on a `seq` change. While you own an object its stream is kept at your live pose, so if you lose it the handoff glides from where it is. Posed players use §10.1. Read `StateRaw` for gameplay.
- **Views are rewritten in place.** `State` is the same dictionary every frame, updated by `Tick()` (about 230 bytes of allocation per frame for five moving streams, all of it boxed numbers that changed). Copy it if you need a frame's values later.
- **Objects.** An accepted `Claim` makes you the owner at once: `SetObject` right after `await Claim` is published, before the relay's state patch arrives.
- **Matchmaking.** Network errors and 5xx are retried for as long as you search, with backoff capped at 8 s, so a relay deploy (§14) does not end the search. `Failed` fires only for 426, for a 400/401/403 that repeats with a fresh token, or for bad options. A match seat that closes with 4401, 4409, 4002 or 1000 stops (`Disconnected`); any other close searches again.
- **Typed pose (§6.6).** It is experimental and off by default (`GenexConnectOptions.Pose`). Posed peers are always decoded.
- **WebGL reconnect.** The SDK's in-place reconnect never retries in a WebGL player (it waits on `Task.Delay`), so the session runs each scheduled attempt itself (`GenexConnectOptions.DriveReconnects`, on in WebGL players only), once and 250 ms past due, on the same nine-attempt ladder.

## Identity

Read a fresh `embed:play` token before every join (§3.2). Never cache or log it. Pass a provider as `GetEmbedToken`:

- **WebGL.** Use `GenexWebGL.EmbedToken` / `RequestAuth()`. Your WebGL template must expose the embed SDK:
  ```html
  <script type="module">
    import * as genexEmbed from "https://cdn.jsdelivr.net/npm/@genex-ai/embed-sdk@0.33.0/+esm";
    genexEmbed.initEmbed({ slug: "my-game", apiUrl: "https://api.genex.games", dashboardOrigins: ["https://genex.games"] });
    window.genexEmbed = genexEmbed;
  </script>
  ```
- **Native.** `GenexNativeIdentity` implements [CLI_INTEGRATION.md §6b](../../CLI_INTEGRATION.md):
  1. `TakeLaunchTicket()` + `RedeemTicket(t)` when launched by Genex.
  2. Otherwise `SignInAsGuest()`, or the device code flow: `StartDeviceSignIn()` and then `PollDeviceSignIn()`.

  `TokenProvider` refreshes the token through `/api/embed/session/refresh`.

  When a launcher sets `GENEX_API_URL`, it replaces the API base you pass to the constructor (`ApiBase` shows
  the one in use). Genex Desktop's Play points it at its local gateway when it runs the game in its sandbox;
  the `RelayUrls` that come back already lead through the gateway.

  `AuthorityUrls` holds the authority cluster's URLs from the same answer (`colyseus.authorityUrls`): pass them
  as `GenexAuthorityOptions.Urls` to join a server-authoritative room from a published build.

## Server-authoritative rooms (protocol 4)

In an authority room the server runs the game's room module; nobody can cheat by editing their client. The client sends one input per fixed step and draws what the server decided: your own entity predicted with the room's movement preset (the server's step, bit for bit), everyone else 100 ms behind, interpolated. `GenexAuthoritySession` is separate from `GenexSession`, so relay games are untouched.

```csharp
using Genex.Multiplayer.Authority;

var session = GenexPump.Register(await GenexAuthority.Connect(new GenexAuthorityOptions {
    Urls = authorityUrls,                 // the sign-in answer's colyseus.authorityUrls; Studio: $GENEX_AUTHORITY_URL
    GameId = "my-game", Name = "ada",
    GetEmbedToken = GenexWebGL.EmbedToken,   // or nativeIdentity.TokenProvider; a loopback server needs none
}));
session.On("shot", data => ShowShot(data));                  // events the module emits

void Update() {                                              // GenexPump has already run Frame() this frame
    session.Input.MoveX = Input.GetAxis("Horizontal");
    session.Input.MoveY = Input.GetAxis("Vertical");
    session.Input.Yaw = aim;                                 // radians
    session.Input.Buttons = Input.GetButton("Fire1") ? 1 : 0;
    var me = session.Me;                                     // predicted
    foreach (var e in session.Entities.Values) Draw(e);      // yours predicted, others interpolated
}
```

|---|---|

Always sends `protocol: 4` and `caps: ["physics@1"]` (this package draws physics bodies; a physics room refuses a client without it with 426), plus `"physics@2"` when it predicts them (`PredictPhysics` and a core). A loopback URL without a token provider sends the local placeholder `local:test`. Resolves after the first state. |
| `Input` | A `GenexInput {MoveX, MoveY, MoveZ, Yaw, Pitch, Buttons}`. Mutate it; each due fixed step sends it, sanitized as the server sanitizes it (axes clamped to [-1, 1], angles wrapped to [-π, π), `Buttons` an integer below 2^24). |
| `Frame()` | Decodes the patches that have arrived since the last frame, sends the inputs now due (Colyseus `Predict.Tick`) and advances prediction and interpolation. The decode comes first because Unity runs the socket's posted work only after the scripts' `Update`: a keyframe already here would otherwise be adopted after the frame had sent, one frame's inputs further from its acknowledgement, and where the lead nears `leadMs` the replay is clipped (§17.11). `Frame(now)` draws everything at `now`, however long the decoding took. `GenexPump.Register(session)` calls it every frame before your scripts (`DefaultExecutionOrder(-1000)`); `Register(session, autoFrame: false)` leaves it to you. Nothing is sent while the socket is down, and nothing is replayed after. No heartbeat: a frame with no due step sends nothing. |
| `Me`, `Entity(id)`, `Entities` | `GenexAuthorityEntity {Id, Kind, Owner, IsMine, X, Y, Z, Yaw, VX, VY, VZ, Hp, Flags, Epoch, Data, ServerX…ServerEpoch, Pitch, Duck, Mstate, Cap, ServerPitch, Spin, Fuel, IsBody, Qx…Qw, Lvx…Avz, Sleep, InView, BodyType, BodyKind, Colliders, BodyOffset}` (the body fields are physics bodies', below; `Qw` 1, `InView` true and the rest 0, false or `""` elsewhere; `Pitch` to `ServerPitch` are `firstperson`'s and `Spin` and `Fuel` `vehicle`'s, below; 0, 0, 0, 1, 0, 0 and 0 elsewhere; `Mstate` and `Cap` serve both), rewritten in place by `Frame()`. `Data` is the entity's JSON text; `Server*` is the latest decoded pose, unsmoothed, for logic. An `Epoch` change is a respawn and is never interpolated: another entity's new life is drawn when the render time (`serverNow - 100 ms - rtt/2`) reaches it, which is where the server's lag compensation judges your shots, and until then `Epoch` is the old life's. Your own entity snaps to its new life with the reconcile that carries it, keeping the inputs still in flight (the server applies them to that life), so moving through a respawn costs no correction; its `Epoch` is the life drawn. |
| `Players` | `GenexAuthorityPlayer {Id, Name, Uid, Team, Connected, AvatarUrl, IsMe}`. |
| `PredictProjectile(p)`, `ServerTick`, `DrawnTick`, `RedrawProjectiles()` | Projectiles, below. |
| `SetPhysics(hash)`, `Physics`, `LengthUnit`, `RedrawBodies()`, `PhysicsPrediction` | Physics bodies, below. `RedrawBodies()` draws every body again at this instant (`Frame()` draws them at the frame's). `PhysicsPrediction` is `{Status, Matched, Replayed, PeakResimMs, Fallbacks, Recoveries, Detail}` (§17.11, below). |
| `SetWorld(world)`, `World`, `Prediction` | Firstperson, below. `Prediction` is `{Predicting, Reason, World, RoomWorld}`: `Reason` is `""` while predicting, else `"off"`, `"no_entity"`, `"no_preset"` or `"world_mismatch"`. |
| `IsReady`, `IsConnected`, `IsClosed`, `Id`, `Tick`, `Preset`, `Rtt`, `Telemetry` | `IsReady` turns true at the room clock's first round trip (at most 2 s after the first state); `Me` and `Entities` are empty until then while inputs already flow (`Players` is listed from the first state), because the SDK lerp's render time moves back by rtt/2 when the first RTT sample lands. `Telemetry` counts `InputsSent`, `InputsDropped`, `Reconciles`, `VisibleCorrections` (over 0.05 units), `PeakCorrection`, `Reseeds`, `ReconnectKicks`, and for projectiles `ProjectilesPredicted`, `ProjectilesConfirmed`, `ProjectilesRejected`, `LastProjectileLeadMs`, for physics bodies `BodyStates`, `BodySnaps` (a body's first state counts) and `PeakBodyCorrection`, and the prediction step's cost: `PredictionSteps` (every replayed input counts), `PredictionStepMs` (their total) and `PeakFramePredictionMs` (the most one `Frame()` spent in them). |
| Deploys | The same session goes back into play by itself, a new seat in a new room (§17.13): `Draining(ms)`, `Rejoining(attempt, code, ms)`, `Rejoined`. `GenexAuthorityOptions.Rejoin = false` makes that close final |
| Events | `Reconnecting(attempt, code)`, `Reconnected` (prediction re-seeded), `Disconnected(code)` (4500 halted, 4501 module fault, 4003 reconnect gave up), `ServerRestart`; `On(type, handler)` for module events. |
| `Leave()` | Leaves on purpose; raises no `Disconnected`. |

Refusals throw `GenexJoinException`: `NotEntitled` (402, final), `ModuleUnavailable` (424), `RoomQuota` (429, try later), `ProtocolUnsupported` (426, the game needs an update), `CapacityRefused` (503, thrown only after the retry ladder).

- **Presets.** `GenexPresets.StepTopdown` (`Presets.cs`) and `GenexFirstperson.Step` (`Firstperson.cs`) port `packages/multiplayer/src/authority/presets.ts` in double math with a `(float)` rounding wherever PROTOCOL.md §17.7 says; `GenexSmoke presets` holds both bit for bit to the shared vectors. A room whose preset this port does not know is drawn unpredicted.
- **Firstperson** and **projectiles**, below.
- **The schema** (`Runtime/Core/Authority/AuthoritySchema.cs`) is generated from `packages/multiplayer/src/authority/schema.ts` by `packages/multiplayer/scripts/gen-engine-schema.ts`; never edit it by hand. It lives in its own namespace, `Genex.Multiplayer.Authority.Wire`, which must hold the schema classes and nothing else: the SDK binds the handshake's types among every type in the root state's namespace and assembly (see Limits). Every constructor and field carries `[Preserve]`, because UnityLinker never reads a `link.xml` inside a package and high stripping removed an unread field.
- **WebGL.** The C# core runs in the browser as on desktop. The SDK's in-place reconnect never retries there (it waits on `Task.Delay`), so the session runs each scheduled attempt itself (`DriveReconnects`), once and 250 ms past due, on the same nine-attempt ladder.

### Firstperson (PROTOCOL.md §17.7)

A `firstperson` room moves each body the way Counter-Strike does (Source movement: friction, ground and air acceleration, air-strafing, a free step up ledges, sticking to slopes and stairs, ducking and crouch-jumping, a swept hull sliding along what it hits) through a static collision world of boxes and ramps the room module exports beside its config. Your own body is predicted with the same step the server runs, through the same world: hand the session the world your room module exports, value for value.

```csharp
// The world your room module exports (defineRoom({ ..., world })), as JSON or as arrays: boxes are
// [minX, minY, minZ, maxX, maxY, maxZ], ramps [minX, minY, minZ, maxX, maxY, maxZ, axis, lo, hi]
// (a top rising along x for axis 0 or y for axis 1, from lo at that axis's min end to hi at its max end).
var world = GenexFirstpersonWorld.FromJson(worldJsonTextAsset.text);    // or GenexFirstpersonWorld.Create(boxes, ramps)
session.SetWorld(world);                     // or GenexAuthorityOptions.World before Connect
if (!session.Prediction.Predicting) Debug.LogWarning(session.Prediction.Reason);   // "world_mismatch": not the room's world

void Update() {                              // GenexPump has already run Frame() this frame
    // Camera-relative keys turned into WORLD axes by your view yaw: the step uses no trigonometry.
    GenexFirstperson.WishDirection(Input.GetAxis("Vertical"), Input.GetAxis("Horizontal"), viewYaw, out var mx, out var my);
    session.Input.MoveX = mx;
    session.Input.MoveY = my;
    session.Input.Yaw = viewYaw;             // stored and drawn only, as is Pitch (+ looks up)
    session.Input.Pitch = viewPitch;
    session.Input.Buttons = (Input.GetButton("Jump") ? 1 : 0) | (Input.GetKey(KeyCode.LeftControl) ? 2 : 0) | (Input.GetKey(KeyCode.LeftShift) ? 4 : 0);
    var me = session.Me;                     // predicted: X, Y, Z (the feet), Pitch, Duck, Mstate; Cap is the server's
    var eye = me.Z + 64 + (46 - 64) * me.Duck;   // cs2's eye heights in Source units; the step has none
}
```

- **The world.** A real level comes from [From a level to a world](#from-a-level-to-a-world). `GenexFirstpersonWorld.Create(boxes, ramps)`, `FromJson(text)` and `FromValue(value)` validate it by §17.7's rules (at most 32768 boxes and 4096 ramps, every value a float32 of magnitude at most 1e9, min < max on every axis, a ramp's `axis` 0 or 1 with `minZ ≤ lo, hi` and `maxZ = max(lo, hi)`) and throw `GenexWorldException` (with the `Path` of the first bad value, in the reference's order) otherwise; anything but an object, JSON `null` too, is refused at `$` (the empty world is `GenexFirstpersonWorld.Empty`). `FromJson` reads numbers with the package's own correctly rounded reader, so a world a JS exporter wrote (`JSON.stringify` of float32s) reads value for value: Unity's own `double.Parse` (Mono and IL2CPP) is not correctly rounded and read the float32 `-0.3616481423377991` one ulp off, which is no float32. Its `Hash` is the 32-bit FNV-1a the room's `params.world` carries. Your entity is predicted only while the two are equal; otherwise it is drawn from the server's state like everyone else (behind, never corrected) and `Prediction.Reason` is `"world_mismatch"`, logged once. Until `SetWorld` your world is the empty one. Calling `SetWorld` with another world re-seeds the prediction from the server with the inputs in flight replayed on top. Keep the world in a file both the module and the game load (a JSON `TextAsset` in Unity), so the two cannot drift: one value rounded differently is another hash.
- **The broadphase.** A world is compiled into a bounding-volume tree over its solids' boxes (x, y and z), which only filters: each test asks it for the solids that could matter, in ascending index, and runs the exact test on each, so the result is bit-identical to visiting every solid (`GenexSmoke firstperson-diff` holds it to brute force over random worlds, stacked columns, map-wide solids and a 1500-box level). On that level a step costs about 13 µs through the tree on .NET 8 and 7 µs in a Mono player, against 260 and 190 µs visiting every solid; a frame that replays eight inputs (150 ms RTT at 30 Hz) about 0.1 ms. `World.WithBroadphase(false)` is brute force, for tests.
- **Axes.** x/y is the ground plane and +z is up, in the room module's units (the defaults are Source units, about an inch: a game in metres sets every distance, speed and acceleration parameter in metres). Unity is y-up and left-handed: map a Genex point to Unity as `new Vector3((float)x, (float)z, (float)y)` and back as `(u.x, u.z, u.y)`, the same swap for a box's min and max corners. That swap also turns the handedness right, so a Genex yaw (radians counter-clockwise from +x, seen from above) is `Mathf.PI / 2 - transform.eulerAngles.y * Mathf.Deg2Rad` for a Unity heading (degrees clockwise from +z), and a Genex pitch (+ up) is minus Unity's x rotation in radians (+ down).
- **The body's fields.** `Pitch` is your input's, wrapped and held to the room's `pitchLimit` (others' interpolated straight, never along a short arc: at the widest limit, float32(π/2), +limit to −limit is more than π, and held the same way); `Duck` is 0 standing to 1 ducked; `Mstate` holds `GenexFirstperson.OnGround` (1), `Ducking` (2) and `JumpHeld` (4); `Cap` is the speed multiplier the module writes (a weapon's, a wound's), read by the step and never written by it. A respawn re-seeds all of them.
- **Tick rate.** Air-strafing gains speed with the input rate, so a `firstperson` module should ask for `tickHz` 60 (§17.7).
- **Determinism.** As the projectile flight's (below): each operation in §17.7's order, double math, a `(float)` cast only where it says, no fused multiply-add (`-ffp-contract=off` for IL2CPP). Bit-exactness has run on .NET 8, a Mono macOS player and WebGL IL2CPP.

### From a level to a world

Your level's colliders become the room's world in three commands, and the room and your game then load one file, so prediction and the room share a hash. Unity's part is an exporter in the Editor assembly; it writes the engine-neutral [world scene](../../packages/multiplayer/WORLD-SCENE.md) every engine's exporter writes.

1. **Export.** Open the level and use **Genex > Export World Scene...**, or in batch:
   ```bash
   Unity -batchmode -nographics -quit -projectPath . -logFile - \
     -executeMethod Genex.Multiplayer.WorldExport.GenexWorldExporter.RunBatch \
     -genexScene Assets/Scenes/Level.unity -genexOut level.scene.json -genexCharacterLayer Player
   ```
   The batch prints one `GENEX_WORLD_EXPORT` line (counts, what was left out, what moves, warnings) and exits 0, or one `GENEX_WORLD_EXPORT_REFUSED` line per reason and exits 2 with no new file. 3 means the flags were wrong.
2. **Fit.** `genex world fit level.scene.json level.world.json` (the line the export prints). The fit works out what a hull can reach and spends the budget there. A level that will not fit exits 3 with no world, and `--report <file>` names the costliest actors.
3. **Use it, both sides.** The room module exports the file as `world` (`import WORLD from "./level.world.json"`), and the game hands the same file to the session: `GenexFirstpersonWorld.FromJson(worldTextAsset.text)`, then `session.SetWorld(world)` or `GenexAuthorityOptions.World`. Re-export and re-fit when the level changes; a game that ships the file in `Assets/` and in the module cannot drift.

**What the walk reads**, in every loaded scene, inactive objects included so a refusal can name them:

| In the scene | In the file |
|---|---|
| `BoxCollider` | `box`. On the axes after turning (a quarter turn included) it has no `axes` and stays exact in the fit |
| `SphereCollider`, `CapsuleCollider` | `sphere`, `capsule`, with the widest scale, as Unity's physics takes it. A capsule too short for a segment is a sphere |
| `MeshCollider` | `mesh`; convex is `hull` (past 4,096 points, `mesh` with a warning) |
| `TerrainCollider` | `heightfield`. Unity turns and scales no terrain, so only its position counts. A hole is a cell and the format's holes are at vertices: every corner of a holed cell is a hole, so a hole can grow by a cell and never closes |
| The terrain's tree colliders | One actor a tree, `Hills/Tree 3`, while Enable Tree Colliders is on |
| A disabled collider, an inactive object, a trigger | Left out and counted in the report |
| A `GenexWorldSpawn`, or an object tagged `Respawn` | A spawn. A level with none is refused |
| 2D colliders, a Terrain with no `TerrainCollider`, other collider types | Left out with a `not_read` warning |

Scaled, turned and mirrored parents count: a primitive takes its object's world position, rotation and lossy scale, as PhysX does, a mesh the whole local-to-world matrix. A mirror changes where a primitive's centre lands and nothing else about it, and a mirrored mesh's triangles are written turned so they still face out. A negative box size or radius is a length. `Tests~/WorldExport` shoots 12,000 rays through Unity's physics and the file and compares every hit, and 4,800 more at mirrored and sheared colliders. The one place they part is the rim a terrain hole grows by, above.

**What moves.** A `Rigidbody` (kinematic too) with everything under it, an `ArticulationBody`, a `CharacterController`, an `Animator` with a controller, an `Animation` with a clip or a `PlayableDirector` above the collider, and a `GenexWorldActor` with **Movable** ticked: each is written tagged `movable` and named in the report, and no fit bakes it. Your game moves those itself (a module's posed solids, §17.7). Nothing can read what a script does, so an object not marked Static with a script on it or its parent is baked and warned about (`may_move`): tick **Movable** if it moves. **Prop** on the same component marks what a budget may cut first; **Leave Out** keeps something out of the world altogether. A `prop` tag on an object says the same as **Prop**, and any other Unity tag is carried along.

**Layers are channels.** A collider stops a hull (`move`) when the layer collision matrix lets its layer touch your character's (`-genexCharacterLayer`, the window's Character layer; default `Default`), and a collider's Exclude and Include Layers count. It stops a bullet (`shot`) when its layer is in the shot layers (`-genexShotLayers`, default `Physics.DefaultRaycastLayers`). So `Ignore Raycast` is a clip wall as it stands. `-genexLayerChannels Clip:move,Glass:shot,Fx:none,Wall:both` overrides layers by name. Stopping neither leaves it out.

**Units.** A Unity point `(x, y, z)` in metres is the room's `(x·u, z·u, y·u)`, with `u` units a metre (`-genexUnitsPerMeter`, default 39.37, Source units, what `firstperson`'s defaults are in). Draw the room's numbers back with `/ u`. Keep it at 39.37: `firstperson`'s step compares squared distances in world units (§17.7), so in metres a walk slower than about 3.8 m/s never climbs a ledge, and an export under 10 units a metre warns `units_too_small`. A room with its own hull says so with `-genexHull radius,height,crouchHeight,step,jump,leap`, in room units. Left out, the fit takes the Source hull scaled by `u`.

**What it refuses.** Every reason at once, each with its actor, and nothing is written. A file from an earlier export stays as it was.

| Code | When |
|---|---|
| `not_finite` | A NaN or infinity in a transform, a collider's numbers, a vertex, a height or a spawn. Unity's API will not set one; a scene file can hold one |
| `zero_scale` | A scale of zero along an axis, or a matrix that flattens a mesh to no volume |
| `huge_scale` | Anything past 2^24 units (about 426 km at 39.37), where a float32 no longer holds whole units |
| `non_readable_mesh` | A mesh whose triangles nothing can read. An imported model with Read/Write off is fine: the editor reads it, as its own cooking does. This is a run-time mesh that called `UploadMeshData(true)` |
| `empty_scene` | No static collider a hull can stand on, with the counts of what was left out |
| `no_spawn` | No `GenexWorldSpawn` and nothing tagged `Respawn` |
| `bad_units` | Units a metre not above zero |

A moving object's bad transform refuses nothing: it is never part of the world. It stays named, with no surface and a warning.

**Numbers.** The file is written in thousandths of a unit through integer arithmetic, so no runtime's float printer is involved and a matrix's last bit rarely reaches it. Two machines may still round one value differently, so treat the fitted world as the contract: commit `level.world.json`, and both sides read those values whatever machine exported.

**Windows.** The exporter is plain editor C# with no platform code, and the hash is in the world file, so a Windows export needs nothing different; the same scene on Windows has not been run (the editor here is macOS). **Licence.** The rules (`Editor/Core/WorldSceneExport.cs`, no `UnityEngine`) run with no licence: `GenexSmoke world-export` holds them to `conformance/authority/world-scene/unity-export.json` in `engines.yml`. The walk, the rays and the player need a licensed editor: `Tests~/WorldExport/run.sh checks` on such a machine.

### Vehicle (PROTOCOL.md §17.7)

A `vehicle` room drives each body as an arcade car on Rocket League's ground and air handling, kept level (no pitch or roll): throttle, braking and coasting, boost from a fuel tank, grip that turns the velocity with the heading (less of it while drift is held, so the tail slides), a turn rate that grows with speed and mirrors in reverse, a jump and steering in the air. It moves the same hull through the same collision world as `firstperson` (`GenexFirstpersonWorld`, `SetWorld`, the same hash gate and `Prediction`), with that preset's collision procedures, except that on the ground a face the car can drive on carries it up at full speed and a steeper one is a wall. A ball is usually a server projectile the module re-launches (§17.9's note): it is drawn at the server's present like any other projectile, with nothing more to do.

```csharp
session.SetWorld(GenexFirstpersonWorld.FromJson(arenaWorldJson.text));   // the world the room module exports

void Update() {                                 // GenexPump has already run Frame() this frame
    session.Input.MoveY = Input.GetAxis("Vertical");     // the throttle: below 0 brakes, then reverses
    session.Input.MoveX = Input.GetAxis("Horizontal");   // the steer: +1 (the right key) steers RIGHT
    session.Input.Buttons = (Input.GetButton("Jump") ? 1 : 0) | (Input.GetKey(KeyCode.LeftShift) ? 2 : 0) | (Input.GetKey(KeyCode.LeftControl) ? 4 : 0);   // jump, boost, drift
    var me = session.Me;                        // predicted: X, Y, Z (the hull's base), Yaw, Spin, Fuel, Mstate; Cap is the server's
    car.position = new Vector3((float)me.X, (float)me.Z, (float)me.Y);
    car.rotation = Quaternion.Euler(0, 90f - (float)me.Yaw * Mathf.Rad2Deg, 0);
    boostBar.fillAmount = (float)me.Fuel;       // wheels and skid marks from Spin (rad/s, + toward +yaw)
}
```

- **The step.** `GenexVehicle.Step` (`Vehicle.cs`) ports §17.7's `vehicle`: `GenexVehicle.ResolveParams` reads a room's parameters (real ones used as float32, the masks, `substeps` and `world` exactly; one whose float32 is 0 where the range excludes 0 is refused, as the server refuses it). The heading is turned with §17.7's portable sine and cosine, `GenexPresets.PSinCos` (and `PSin`, `PCos`), never `Math.Sin`/`Math.Cos`, which differ in the last bit between .NET, Mono, V8 and C libraries; their constants are built from their bits, since Unity's own `double.Parse` is not correctly rounded. The step is held bit for bit to `vehicle.json` (73 cases, with and without the broadphase, the ten `discriminate-` cases at tolerance 0) and the sine and cosine to `sincos.json` (566 samples, tolerance 0), on .NET 8, a Mono macOS player and WebGL IL2CPP.
- **Steer sign and axes.** `MoveY` is the throttle and `MoveX` the steer: **+1 steers right**, toward −yaw, so your right key sends +1 as it does for any other right input (the step negates it: a positive steer turns toward +yaw). `Yaw`, `Pitch` and `MoveZ` are unused: the heading is the car's state, not your input. Buttons are the room's `jumpBit`, `boostBit` and `driftBit` (1, 2 and 4 by default). x/y is the ground plane and +z is up, in the module's units (the defaults are Rocket League's, about a centimetre). In Unity a Genex point is `new Vector3(x, z, y)` and back `(u.x, u.z, u.y)`; the heading (radians counter-clockwise from +x, seen from above) is the Unity yaw `90 - yaw · Rad2Deg` degrees (clockwise from +z), and a Unity heading `h` degrees is the Genex `yaw = (90 - h) · Deg2Rad`. The hull is a square footprint that does not turn with the heading (100 across with the defaults, for a car about 118 × 84).
- **The body's fields.** `Spin` is the yaw rate (rad/s, positive toward +yaw) and `Fuel` the boost tank ([0, 1]): yours predicted, others' the server's latest. `Mstate` holds `GenexVehicle.OnGround` (1) and `JumpHeld` (4); `Cap` (the module's) scales both top speeds and never an acceleration. The module refuels by writing `Fuel`, and a respawn (an epoch bump, a kickoff) re-seeds all of them.
- **The heading is drawn as an angle.** Your own `Yaw` is drawn along the short arc across ±π: the SDK reconciler eases a field as a plain number, which for a heading that wraps sweeps the long way round for one step, so the session reads the reconciler's previous step and correction (by reflection, `GenexAuthoritySession.AngleRenderAvailable`; found in .NET, Mono and WebGL IL2CPP under high stripping) and interpolates the heading itself, and folds a correction measured across the seam to the short arc: the reconcile re-bases the correction and the same frame's tick decays it, so the session rebuilds it from the heading and correction it read before the tick, folds that and carries it through the same decay (folding the decayed value drew a 3.1 to −3.1 jump through 1.2; `authority-edge.ts yaw-fold`). Others' headings are interpolated as angles by the SDK's lerp. Either way `Yaw` is in [−π, π).
- **Tick rate.** The grip and the yaw rate integrate once per sub-step, so the car differs slightly between rates (every engine still gives the same one); a `vehicle` module should ask for `tickHz` 60 (§17.7).

### Projectiles (PROTOCOL.md §17.9)

A projectile is an entity the room module launched with `ctx.projectiles.launch(...)`: the server writes its launch once (`T0`, the launch tick, plus `X..VZ` and gravity `G`) and every client computes where it is from that. `GenexAuthorityEntity.IsProjectile` (`T0 > 0`) marks one; its `X..VZ` are its flight (`GenexProjectile.At`, `Projectile.cs`) at the room's present, `ServerTick` = `(serverNow - tickOrigin) · tickHz / 1000`, never interpolated, so another player's bolt is drawn where the server has it, not 100 ms behind. A projectile is never `Me` (your own entity is the first you own with `T0 = 0`). `Src` is the seat that fired it.

Your own shot is drawn the moment you fire it. Predict it while staging the input that fires, before the `Frame()` that sends it (with `GenexPump`, in your `Update`). The firing input goes out on the next fixed step that falls due, which is not necessarily the next frame: at 60 fps and a 30 Hz room every other `Frame()` sends nothing. So hold the fire button until `Telemetry.InputsSent` has moved past the count at the fire, and release it only then. A button cleared in the next `Update` is often cleared before any input carried it: the prediction then stands for an input that fires nothing, and the shot appears and vanishes.

```csharp
int fireSentAt = -1;                                         // InputsSent when the fire was staged; -1 = none pending

void Update() {
    session.Input.Yaw = aim;
    if (fireSentAt >= 0 && session.Telemetry.InputsSent > fireSentAt) {
        session.Input.Buttons = 0;                           // the firing input went out: only it fires
        fireSentAt = -1;
    }
    if (fireSentAt < 0 && Input.GetButtonDown("Fire1") && CanFire()) {
        session.Input.Buttons = 1;                           // held until the next due step sends it
        fireSentAt = session.Telemetry.InputsSent;
        var me = session.Me;
        var aimF = (double)(float)aim;                       // the yaw the server's sanitizer keeps
        shotId = session.PredictProjectile(new GenexProjectilePrediction {
            Kind = "bolt", X = me.X, Y = me.Y, Z = 0,
            VX = Math.Cos(aimF) * 18, VY = Math.Sin(aimF) * 18, VZ = 0, G = 0,   // what the module launches
        });
    }
    foreach (var e in session.Entities.Values)
        if (e.IsProjectile) DrawBolt(e.Id, e.X, e.Y, e.Z);  // key your sprite on Id: it never changes
}
```

Every input that one `Frame()` sends carries the staged buttons: in a frame with two due steps both fire, so a module without a cooldown launches twice (the second one unpredicted, drawn without the lead). The probe (`Tests~/GenexSmoke/ProjectileSmoke.cs`) fires this way.

- **The id** is the one the server gives the shot, `<seat>.<seq>.<n>`: `seq` is the sequence of the input being staged (`seqBase` of your player plus the inputs this socket sent, plus one; it goes on across a reconnect) and `n` your launches in that input. `Entities` lists the prediction under it (`IsPredicted`, a fractional `T0`) until the server's projectile of that id arrives, then the server's in the same view: drawn your input lead ahead (the server's launch instant minus your fire's, `LastProjectileLeadMs`) while `Src` is still you, so it flies on from where the prediction was instead of snapping back by lead × speed. One the server re-launches as its own (a bounce from its step, `Src` becomes `""`) is drawn at the present like any other.
- **A shot the server never shows** (refused in a cooldown, a dead shooter, or a hit before any state patch carried it) is dropped as soon as a patch acknowledging its firing input arrives without it, about a round trip after the fire. One fired on a socket that then dropped is dropped at the reconnect's first state unless that state confirms it: the server consumed what it got of that socket's inputs before sending it, and a lost input's sequence is used again on the new socket, so the next shot would reuse the id and be confirmed against the lost prediction (a lead of the whole reconnect). One nothing else settles (its input lost to a drop that has not reconnected yet) goes after max(2·RTT, 600 ms). The module's events say which it was. While the socket is down (from `Reconnecting` until `Reconnected`) `PredictProjectile` predicts nothing and returns `""`: no input is queued across a drop, so the fire would never be sent. This is the Colyseus C# SDK's own predicted-spawn store (`Predict.Spawns`, `PredictedSpawns`), correlated by id.
- **When to read.** `Frame()` draws every projectile at one tick, `DrawnTick`. A projectile moves between frames: to read one at another instant (a hit test, a tool), call `RedrawProjectiles()`, which redraws them all at this instant and returns the tick.
- **Determinism.** `GenexProjectile.At` is only `+ - * /` in the reference's order, each its own statement, with a `(float)` rounding on every position and `vz` and `-0` written as 0; `GenexSmoke presets` holds it bit for bit to `projectile.json` (whose `order-*` cases catch a reordered, float32-only or fused evaluation). The .NET and Mono JITs never fuse a multiply and an add. IL2CPP emits each operation through its own inline helper (`il2cpp_codegen_add`, `il2cpp_codegen_multiply`), so clang's default contraction, which fuses only inside one source expression, finds nothing to fuse; PROTOCOL.md §17.7 still asks IL2CPP output to be compiled with contraction off, so add `PlayerSettings.SetAdditionalIl2CppArgs("--compiler-flags=-ffp-contract=off")` to your build script (the probe's WebGL build does, and the flag reaches every emcc compile). Bit-exactness has run on .NET 8, a Mono macOS player and WebGL IL2CPP only; IL2CPP on ARM (iOS, Android, Apple-silicon Mac players) has not run, because the editor here has none of those modules. Offline, the probe's WebGL IL2CPP output for this package (its three C++ files) compiled for arm64 with Apple clang 21 at `-O3` has no fused multiply-add at clang's default contraction (`-ffp-contract=on`) and 137 with `-ffp-contract=fast` (among them in `PSinCos`, the vehicle, firstperson and topdown steps and `GenexProjectile.At`): the helpers keep the default from fusing, and a build flag that allows more is what breaks the bits.

### Physics bodies (PROTOCOL.md §17.10)

In a physics room the server simulates rigid bodies (crates, balls, doors on joints) and every client only draws them; nobody predicts them in this release. A body is an entity with a descriptor in the room's `bodies`: `IsBody` marks it, and `BodyType` (`dynamic`, `fixed`, `kinematic`), `BodyKind` and `Colliders` (the colliders' JSON, to build its mesh from) are its descriptor. A body is never `Me`, even one your seat owns.

```csharp
foreach (var e in session.Entities.Values)
    if (e.IsBody) DrawCrate(e.Id, new Vector3((float)e.X, (float)e.Z, (float)e.Y),             // z up on the wire, y up in Unity
                            new Quaternion(-(float)e.Qx, -(float)e.Qz, -(float)e.Qy, (float)e.Qw)); // and the handedness flips
```

- **At the server's present.** A body is drawn where the server has it now (`ServerTick`), never 100 ms behind like other entities: the state a patch carried (the body at that patch's tick + 1) is extrapolated by its velocities, at most 250 ms past it (moved back a tick at most when it lands before its tick), and not at all while `Sleep` is set. `Lvx…Lvz` are metres per second (times `LengthUnit` for room units per second), `Avx…Avz` rad/s in world axes.
- **Eased corrections.** When a newer state disagrees with what was drawn, the difference is drawn away with a 100 ms time constant, never jumped; `BodyOffset` is what is left of it. An `Epoch` change (the module respawned the body), a body spawned again, or a correction over one metre (`LengthUnit` units) snaps instead.
- **Out of view.** A physics room sends each client its nearest 100 bodies every patch and the others in turn; a body that left your view stays in `Entities` with `InView` false, held at its last state, until it comes back.
- **Your own physics copy.** A game that runs a copy of the room's physics world passes its hash to `SetPhysics` (or `GenexAuthorityOptions.Physics`); `Physics.Reason` is `"physics_mismatch"` while the room's (`Physics.RoomPhysics`) differs. Nothing steps a copy in this release, so that report is the whole effect.
- **The math.** Plain double arithmetic (`PhysicsDraw.cs`: `GenexBodyDrawer`, `GenexPhysicsDraw.Extrapolate`, `GenexQuat`); `GenexSmoke physics-draw` holds it to the shared `physics-draw.json` within its 1e-4 tolerance.

### Physics prediction (PROTOCOL.md §17.11)

A predicting physics room (the default for a new one) sends keyframes: every K ticks its state is exactly the canonical state of its world. This package steps the bodies near you in a world of its own, on the native Genex Physics core it ships (`Runtime/Plugins/GenexPhysics`, the same core the TypeScript SDK runs as WebAssembly, so both get the same `stateHash` after every tick), and draws them at your present instead of the server's: `IsPredicted` marks such a body. It is on by default (`PredictPhysics`); the join then declares `physics@2`.

- **The core.** `GenexPhysicsNativeCore.Load` loads the C ABI (`genex_physics.h`, ABI version 1) over P/Invoke: the macOS universal dylib (editor and players), Windows x64 DLL, Linux x64 .so, Android arm64-v8a .so and the iOS xcframework (statically linked, `__Internal`; Unity 2023.2 or later imports an `.xcframework`), each with its import settings (`.meta`). WebGL has no native core: there bodies are drawn §17.10's way (`PhysicsPrediction.Status` `unavailable`). `GenexAuthorityOptions.PhysicsCore` hands over another `IGenexPhysicsCore`. A library whose ABI is not 1 or whose `buildId` is not the pinned build's (`GenexPhysicsNativeCore.PinnedBuildPrefix`) is refused. Provenance and sha256s: `Runtime/Plugins/GenexPhysics/PROVENANCE.json`.
- **What it does.** The core loads only once a room sends keyframes, after a self-test scene (`self_test` when it fails). The client world holds the room's static world (the one you gave `World`, which must give the room's `physicsHash`: else `mismatch`), the whole contact islands of bodies in view with a descriptor (nearest you first, up to 128, then 64 and 32 by the replay budget below), every seat's preset body (yours from your prediction, the others extrapolated, or under their last input decayed in an `inputDecay` room) and the joints among them. Your preset body is posed from the input-sequence ring: your position and velocity after each input, stepped again from the state's own entity at every keyframe, so a replay never poses it where an older prediction, since corrected, had it. Each keyframe is adopted by skip-on-match (nothing redone when the world predicted it exactly) or by import and replay of your inputs since its ack, at most `ceil(leadMs · tickHz / 1000) + K − 1`. A body that moves at a replay eases from where it was drawn, critically damped keeping the last correction's rate (τ 300 ms up to 0.25 m, 100 ms from 1 m), or snaps over 2 m (a `player` or `vehicle` body) or 6 m (any other). Module kinematic bodies (doors, platforms) are posed from the keyframe and drawn §17.10's way. More than 2% of pure bodies mismatching over the last 500 compared turns prediction off (`diverged`).
- **Budgets.** A replay's cost is the wall clock around one adoption's rebuild and replay. The client judges the last 60 costs once it has 20: over budget when their median is over the budget or their p90 over twice it (one slow replay, a GC pause, never decides). Over budget, the set shrinks to the next of 128, 64, 32 that takes fewer bodies than the last choice could (a size that would choose the same bodies is skipped); with none left the status is `cpu` and bodies are drawn §17.10's way. `cpu` is not final: every 500 ms one keyframe is adopted by a full replay (a probe, not drawn), and after 4 probes in a row each at most half the budget the status is `on` again; a full window whose p90 is at most half the budget grows a shrunken set back one size. The budget is `PhysicsResimBudgetMs` (4 ms on desktop, 5 in a mobile player), or `PhysicsBudgetMs` when that is a finite number over 0 (anything else is ignored). `PhysicsPrediction.Fallbacks` and `Recoveries` count the turns to `cpu` and back.
- **The room module's rules.** Module commands arrive as corrections, except four kinds of rule the module declares as pure functions of the state and runs itself; hand the session the very same function and it is predicted. `Contacts` (`GenexContactRule`, §17.11 *Seat contacts*: what the module does to two seats' entities after each tick's preset steps, a car-to-car bump, `a` the lower id) runs in your own entity's prediction after each input, against every other seat's entity in the latest state moved on by its velocity to that input's tick, in id order; your fields it changed (`x y z vx vy vz yaw spin`) are kept as float32. `BodyRule` (`GenexPredictBodyRule`, §17.11 *Body rules*: velocities the module sets on its dynamic bodies from the seats and the bodies, a ball's scripted hit) runs in the client world before every predicted step: it reads every seat at that tick (`GenexRuleTick.Seats`, key order, position and velocity) and a dynamic body as the last step left it (`Body(key, out body)`), and adds the velocities to set. `SeatRule` (`GenexSeatRule`, §17.11 *Seat rules*: what the module does to a seat's own entity at a tick it announced in advance, a kickoff that holds cars with `cap` 0 and sets `cap` 1 in its step of tick `go`) runs on your own entity before each predicted input, at the tick that input is applied on (`GenexSeatRules.TickOf`: the state's `tick` + seq − ack, one input a tick), in the reconciler's steps, a new world's re-prediction and the ring; it sees the fields your prediction mirrors by name (the vehicle and firstperson presets mirror `cap`), and what it writes to them is predicted (a name not mirrored is dropped). In an `inputDecay` room it also runs on each other seat's body before each of its steps, at the keyframe's tick + j, so a release is predicted, not learned a round trip late. `KinematicRule` (`GenexPredictKinematicRule`, §17.11 *Kinematic rules*: where the module poses its kinematic bodies, a gate or a moving floor, as a pure function of key and tick) poses each module kinematic body it answers for with `rule(key, tick + 1)` before every predicted step, as the module's `setNextKinematicPose` does, and the predictor draws it as a predicted body, also outside the simulated set (the rule's pose eased toward the next tick's); without it they hold each keyframe's pose and are drawn from the server's states. A rule that throws throws out of the session's call, as in the TypeScript SDK; a non-finite velocity is refused by the core. `Tests~/CarBall/Assets/CarBall/CarBallRules.cs` is Torque Pitch's three.
- **Input repeat** (§17.11 *Input pacing*, *The setting*) is the room's setting (`config.inputs`): the session sends `repeat@1` and reads it from the state's preset text (`GenexInputRepeat.SettingOf`). On, the shadow input handle your prediction is compared through (`GenexShadowInput`) is acked at what its `GenexReconcilerAckHold` tells from `StateThrough(ack, inRep, On)` (§17.11 *The reconciler's ack*): `ack + inRep` once sent; past the inputs sent, a hitch, it waits at the ack told last; and while its replay ring no longer holds every input after that ack it is held back, so a state still more than a ring behind your sends after a long downlink hold is not reconciled with the oldest inputs skipped. The throttle asks for one more input of lead after a starve; off (a `vehicle-arena` room, such as car-ball), the room repeats nothing, the comparison is at the plain ack and the throttle never runs. GenexSmoke `input-repeat` holds both to `input-repeat.json` (`clients`, `reconciles`, `throttle`, `seatClock`, `settings`, `reconcilerAck`).
- **Drawing other seats.** In a predicting room (its `physDesc` set) every patch is one keyframe, so other entities (not bodies, not projectiles) are drawn from samples timed by their keyframe's tick (`tickOrigin + tick / tickHz`), not by the patch's server stamp, which is up to a tick late and shared by every tick a late call caught up (`TickDrawing.cs`, `GenexTickDrawing`): each is sampled once the whole patch is decoded and only when the state's `tick` is its `keyframe`; a sample after a gap of more than a keyframe period first repeats the held pose one period earlier; a new life (an epoch) is never interpolated into, and the `Epoch` drawn is the sample's, so the output spring (`RemoteSmoothMs`) snaps on the frame the pose changes life. `RemoteSamples = Patch` keeps the server stamp (for comparison). Still `RenderDelayMs` behind, so lag compensation still rewinds within a tick of what was drawn; `Telemetry.TickKeyframes` counts the keyframes sampled. With a seat contact rule (`Contacts`) the other seats are drawn as `SeatDrawing` says. `Predicted`, the default (*Drawing other seats*, `predicted`, the Rocket League model): every other seat is predicted on your entity's clock by `GenexSeatWorld` (`SeatPredict.cs`), stepped from the latest state by the room preset under its last applied input (`remotePredict: hold`) with the room's whole contact pass (`ContactPass`; `Contacts` once on every pair without one) on every seat, yours included; your own contacts come from that pass, the client world poses those seats' preset bodies where it has them, and each is drawn at the input your entity is drawn at (moved on a smooth clock of its own, `GenexSeatClock`) with a correction eased in as a critically damped offset (`GenexSeatOffset`: τ 70 ms, 30 ms in contact with yours, snapped past 6 m or at a new life, keeping the seat's place and velocity when a new pass arrives and never pulling it back against its drawn motion; `SeatDrawTick`, `SeatDrawLead` and each view's `SeatCorrection` report it). `Separate` draws them on the timeline instead. Both then keep every seat out of yours, never across it, and out of each other (`GenexSeatSeparation.Seats`). `GenexSmoke carball-seat-predict` and `carball-separate` hold them to `carball-seat-predict.json` and `carball-separate.json`. `Timeline` draws them on the timeline only.
- **Status.** `PhysicsPrediction.Status` is `on`, `off` (`PredictPhysics = false`, the client's kill switch, or no predicting room), `loading`, `unavailable`, `mismatch`, `self_test`, `diverged` (also when the core refuses a step inside a replay: the replay ends there) or `cpu`; `Matched` and `Replayed` count keyframes, `PeakResimMs` is the slowest replay. Whatever it says, every body it does not predict is drawn as above.
- **The math.** `PhysicsPredict.cs` (`GenexPhysicsPredictor`) ports the TypeScript predictor line for line, every number handed to the core rounded to float32 as the package's encoder does (`GenexPhysicsJson`); `GenexSmoke physics-predict` holds it to the shared `physics-predict.json`: every adoption, every client `stateHash` bit for bit, every drawn pose within 1e-4. `SeatContacts.cs` (`GenexSeatContacts`, the seat rule's `GenexSeatRules`) is held to `seat-contacts.json` (`GenexSmoke seat-contacts`, tolerance 0); `TickDrawing.cs` to the TypeScript's test cases (`GenexSmoke tick-drawing`: no shared vectors exist).
- **Cost.** A predicted tick crosses the C ABI in one `gxph_world_tick_frame` (the seats' poses, the body rule's velocities and the step, numbers as binary float64 instead of JSON text), replies are read into reused buffers, a body state's numbers straight from the reply, an export's keys into strings the world already holds, and the client world's per-tick lists, rows and drawn states are reused, as are a keyframe's working sets (the chosen islands, the seats, the drawn poses before a replay, the sort buffers and the import's key text): `GenexSmoke physics-predict-bench` reports a car-ball-sized replay's median and p90 ms and GC bytes (on .NET 8 about 1.75 ms and 8.4 KB a 30-tick replay; `GenexSmoke physics-predict` fails a replay that allocates over 12672 bytes). About 84% of a replay is the native core's (`gxph_world_tick_frame` alone 42%), so the C# side has little left to give; an IL2CPP player has not been measured (the editor here has no Mac IL2CPP module).

### The fast channel (PROTOCOL.md §17.12)

On by default: `GenexAuthorityOptions.Fast` is true, and false keeps the seat on the WebSocket. One log line per join names the transport and any fallback (`genex transport: udp fast@1 ...`, `genex transport: websocket, <reason>: ...`; also `session.Fast.Line`). A WebGL player has no sockets: it claims `fast@1` only when the game sets `FastWebTransport` (never yet run in a player), and otherwise its line says `no_udp`. The session claims `fast@1` beside `tick@1` (every input carries the server tick its view was set for, as the TypeScript session writes it). In a room that offers the channel (`__fast { sid, key, url }`) your inputs go by UDP (on WebGL by WebTransport where the game asked, `GenexFastWebSocket`; elsewhere `GenexUdpFastSocket`: a `UdpClient` connected to the `udp://host:port` the room names, polled in `Frame()`; any other url, or one with credentials, a path, a query or a fragment, is refused) in redundant datagrams, their WebSocket frames kept off the socket, and your motion state comes back in snapshots written into the decoded state as a patch would write it (each field through the schema, its change listeners and `OnStateChange` raised), so the reconciler, Predict and every view read one state; a WebSocket patch that would move a field the channel holds is put back, the WebSocket's latest value kept. Your ack is your own seat record's `inAck`; each snapshot is a clock sample. With no snapshot 1 s after the first datagram, or none for 2 s, or when the room says `__fast:off`, the seat sends `__fast:off { last }` and goes on by WebSocket, coming back by itself when the path does (`Fast.Returns`; it never moves before the path is proven, so a network that blocks UDP loses no input), every held field taking the WebSocket's latest value and every input stepped once: the SDK's input encoder writes each frame against the last one it encoded and its lag-compensation stamp against the last one it stamped, so at the fallback the encoder starts over with a full frame and the stamp baseline goes back to the last frame the server got. `Fast` (`GenexFastStatus`) reports `Live`, `Snapshots`, `Fallback`, `MutedFrames` and `DatagramInputs`. The codecs and the client are `FastTransport.cs`, `FastRecords.cs`, `FastClient.cs` and `FastUdp.cs`, held to `packages/multiplayer/test/vectors/fast-transport.json` by `GenexSmoke fast-transport` (every section and hostile row, zero skips) and to the TypeScript client's tests by `GenexSmoke fast-client`; the session is `FastSeat.cs`, which reaches SDK members by reflection (`Runtime/link.xml` keeps them; a build without them never claims `fast@1`). WebGL has no sockets: there `Fast` alone changes nothing.

## Limits

- `Runtime/Unity/GenexPump` has run in Unity 6000.6.6f1 (a Mono macOS player and a WebGL IL2CPP build) only through the authority probe, with auto-framing (`Register(session, autoFrame: false)` has not run in Unity). The relay session has only joined a play room there (the probe's relay check); `GenexWebGL` and `GenexEmbed.jslib` have run only in the WebGL probe against a stubbed `window.genexEmbed` (never the real embed SDK on a Genex page), `GenexTimer.jslib`'s interval is started there but its firing is not checked, and IL2CPP is untested on macOS (the editor's Mac IL2CPP module is not installed).
- **Colyseus C# SDK 0.18.8 defects** (not reported upstream yet; the owner files them):
  1. `Serializer/SchemaSerializer.cs:78` filters handshake candidates with `typeof(Schema).IsAssignableFrom(targetType)` instead of `(t)`, so every type in the root state's namespace and assembly is a candidate, Schema or not, and `CompareTypes` binds the first whose `[Type]` fields match. A helper class or a second schema family in that namespace can bind to the wrong reflection type or leave one unbound ("Local schema mismatch"). Workaround: each wire namespace holds only its schema classes (`GenexSmoke authority-edge --scenario offline` checks the authority one).
  2. `Room.RetryReconnection` waits with `Task.Delay`, which never resumes in a WebGL player: the in-place reconnect never retries there. Both sessions drive the attempts themselves (`DriveReconnects`, `GenexReconnectWatchdog`), checked on .NET with timer continuations dropped (the relay play suite, `authority-edge.ts webgl`); the relay session's has not run in a WebGL build.
  3. On WebGL, `Connection.Drop()` / `CancelConnection()` closes the browser socket with 1006, which browsers refuse (`WebSocketInvalidArgumentException`).
- **Projectiles** have run against the projectile arena's straight bolts only (no gravity in flight there; the lob and every hostile launch are covered by the `projectile.json` vectors alone), at 150 ms RTT, in the .NET console, a Mono macOS player and a WebGL IL2CPP build. A re-launch of your own bolt (a bounce: `Src` becomes `""`) has run in the .NET console only: the conformance bench's bounce check and the smoke's missed bolts (a server projectile re-launched under one id, the vehicle probe's ball, has run in all three runtimes). The lost-fire check has run in the .NET console only (the WebGL probe's runner-cut socket skips it). If a reconnect's resync re-created an entity instance, a confirmed shot of yours in flight would be re-added as a server one and drawn at the present from then on (its lead not kept), as in the TypeScript session; the probe fires its post-reconnect shots after the reconnect, so this is not measured. A WebGL player cuts a console message at 8192 characters, so the probe sends its projectile report in parts.
- **Firstperson** has run against the first-person arena (`fps-arena.js`, 15 boxes and a ramp, the §17.7 defaults at 30 Hz) at 150 ms RTT, in the .NET console, a Mono macOS player and a WebGL IL2CPP build, and against the 1500-box level offline (and inside each player). - **Vehicle** has run against the car arena (`car-arena.js`, 18 boxes and two banks, the §17.7 defaults at 60 Hz) at 150 ms RTT, in the .NET console (the probe and the conformance bench's vehicle checks), a Mono macOS player and a WebGL IL2CPP build, and at 20 and 250 ms RTT in the .NET console only.
